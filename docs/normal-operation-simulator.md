# Repeatable synthetic normal-operation simulator

The flow is registered immutable configuration → deterministic generation → real telemetry admission → isolated simulator history. Python 3.12 and backend dependencies are required. Nothing is added to the API, database schema, migration chain, or analytics worker. Jobs remain pending.

## Configuration and operating envelope

Select an explicit asset/version from the existing paginated registry configuration-history API. The CLI walks pages to find that version; it never substitutes current configuration. Alternatively, `--configuration-json` supplies a complete `ConfigurationResponse` snapshot, including `asset_id`, `version`, `created_at`, ratings and provenance. Offline generation asserts the snapshot reference matches the run; it cannot prove that snapshot exists in the server. Ingestion still checks the asset/configuration foreign key.

Ratings come only from that snapshot. `rated_voltage_v` is RMS voltage on `measurement_side` using `voltage_convention`. `rated_current_a` is RMS **line** current on the same side. No automatic side conversion or turns ratio is inferred. Consistency requires three-phase kVA within 5% of `sqrt(3)*V_LL*I_line/1000` for line-to-line or `3*V_LN*I_line/1000` for phase-to-neutral. A mismatch is rejected rather than silently inventing ratings. These are RMS magnitudes, not phasors or harmonic data; angles, power factor and active power are unavailable.

Time `t` is elapsed measurement time in seconds. Default normalized load is:

`K(t) = 0.60 + 0.15*sin(2*pi*t/3600)`.

For phases R/Y/B, fixed fractional differences `d` are `-0.01/0/+0.01`. Electrical noise `n` is independent deterministic uniform noise in [-1,1]:

- `V_phase(t) = rated_voltage_v * [1 + 0.01*sin(2*pi*t/3600) + d + 0.002*n_voltage]`.
- `I_phase(t) = rated_current_a * K(t) * [1 + d + 0.002*n_current]`.
- `ambient(t) = 25 + 2*sin(2*pi*t/86400)` °C.

The default current envelope is 0.4446–0.759 pu and voltage envelope 0.978–1.022 pu. Phase differences are at most 2% and fractional electrical noise at most 0.5% when overridden. Generator admission requires the conservative apparent-load envelope to fit configured `max_load_pct`, voltage bounds to fit configured minimum/maximum, and the thermal envelope to fit configured top-oil maximum. Maximum phase current must stay <=0.95 pu, minimum baseline load >=0.1 pu, and oil temperature <=95°C regardless of the backend's much broader sanity limits. An initial oil temperature below minimum ambient is rejected. If configured limits are absent, these simulator envelope constraints still apply. They define synthetic normality for this demo; they do not establish validated safe limits for a physical transformer. Hot-spot limits are not evaluated because no hot-spot measurement/model is generated.

## Simple thermal generation

The assumed equilibrium is `target(t) = ambient(t) + thermal_rise_c*K(t)^2`, with default assumed rise 40°C and time constant 60 minutes. For each interval `dt` seconds, hold the previous sample's target constant and update:

`oil_next = target_previous + (oil_previous-target_previous)*exp(-dt/(60*tau_minutes))`.

The first sample uses the supplied initial temperature. Internal thermal state is unrounded; electrical/temperature outputs are rounded to six decimal places. This exact first-order step is gradual, including at load changes. Coarse measurement intervals undersample the sine wave and hold equilibrium constant longer; use intervals small relative to the load period and time constant (defaults/demo 30–60 seconds). The model ignores cooling control, wind, losses calibration, winding dynamics, hot spots and sensor dynamics. Configured thermal model parameters are retained in the snapshot but **not** interpreted by this simple generator. Simulation thermal assumptions are explicitly separate from Person B's prediction model.

Generator-model similarity cannot establish predictive accuracy. Testing a predictor against data generated by the same equations creates circular evidence. Person B needs independent measured or independently validated data, model/parameter uncertainty, and separately retained evaluation labels before making accuracy claims.

## Parameters, reproducibility and sampling

An optional `--parameters-json` object overrides documented defaults; unknown keys and nonfinite values are rejected. All defaults and the full selected configuration are recorded in `run-metadata.json`.

| Parameter | Default | Allowed |
|---|---:|---|
| `load_mean_pu` | 0.60 | 0.2–0.8, plus envelope checks |
| `load_amplitude_pu` | 0.15 | 0–0.3, plus envelope checks |
| `load_period_seconds` | 3600 | >=60 |
| `phase_difference_pu` | 0.01 | 0–0.02 |
| `electrical_noise_pu` | 0.002 | 0–0.005 |
| `voltage_variation_pu` | 0.01 | 0–0.02 |
| `ambient_mean_c` | 25 | 0–35 |
| `ambient_amplitude_c` | 2 | 0–5 |
| `ambient_period_seconds` | 86400 | >=60 |
| `thermal_rise_c` | 40 | >0 to 50 |
| `thermal_time_constant_minutes` | 60 | 1–1440 |
| `oil_level_pct` | null | null or 10–95 |

Oil level remains null with quality `missing` unless explicitly enabled, e.g. `{"oil_level_pct":80}`. There are no fault labels or scenario names in telemetry; scenario/assumptions live only in metadata. This normal-only implementation needs no evaluation-labels file and creates none.

Duration and interval are positive **integer seconds**, duration <=604800, maximum 100000 samples. The half-open interval includes `start + i*interval < start + duration`: count is `ceil(duration/interval)`. Duration 300/interval60 yields five samples; duration301 yields six, last at300. No shortened final step or forced endpoint is emitted. Start must include an explicit timezone offset; it is normalized to UTC and output with `Z`. No wall clock participates in payload generation.

Noise uses SHA-256 of version/seed/sample/channel, without global RNG state or unseeded randomness. Message identifiers are SHA-256-derived 128-bit identifiers with RFC UUID4 version and variant bits (accepted by the existing UUID4 schema). They are deterministic, **not random security identifiers**. Identity includes version, full run specification, selected configuration snapshot, and packet content; changing seed, parameters, reference or snapshot changes identifiers. Reuse the same immutable snapshot and simulator version for reproducibility. Retrying the saved JSONL preserves identifiers exactly. Use a new run ID for changed scenarios; ingestion deduplication remains `(asset, source, run, message_id)` with conflicting content returning 409. Six-decimal outputs are repeatable on the tested Python 3.12 implementation; cross-platform libm/runtime changes are not a byte-identity guarantee across simulator versions.

## Artifacts and commands

The curated four-reading example is `data/sample/normal-operation/`. It is offline synthetic data, not proof that asset `demo-normal-example` is registered. Large runs belong under ignored `data/generated/`. An output directory containing any of the three artifact files is rejected to preserve previous runs.

- `telemetry.jsonl`: one API-ready telemetry schema `1.0.0` packet per line, source simulator, explicit run/configuration, no extra metadata fields.
- `telemetry.csv`: envelope columns `schema_version,message_id,asset_id,source,run_id,configuration_version,timestamp`, then `voltage_r_v,current_r_a,voltage_y_v,current_y_a,voltage_b_v,current_b_a,oil_temperature_c,ambient_temperature_c,oil_level_pct`, then each measurement's `_quality` column. Voltages are configured-convention RMS volts; currents RMS line amperes; temperatures °C; level percent; timestamp ISO UTC. Empty fields mean null; numeric zero is preserved.
- `run-metadata.json`: simulator version, exact snapshot/specification, units in parameter names, seed, assumptions, equations and sampling policy. Never send it to the detector.

**Cloud IDs will not exist automatically on Windows.** Use the locally printed IDs/output from the integration verification. The command shapes are the same. Global flags precede `generate`/`send`. For offline generation add `--configuration-json path/to/configuration-response.json`; `--parameters-json path/to/parameters.json` is optional. Linux equivalents use `.venv/bin/python` from repository root. Generate-only mode performs no POST; absent an explicit file it makes registry GETs only.

Sender immediate delivery is the default. Pacing waits successive measurement-time gaps, with network latency/retries adding delivery delay; this is not a precise real-time scheduler. 201 increments created, 200 increments identical duplicates. Network/timeouts, 408, 429 and 5xx retry at most three times by default (initial attempt plus three), exponential delays starting at0.25s capped at5s, with a10s request timeout. Retries may be set0–10. Request bodies are the same saved bytes for every attempt. 409 conflicts, 422 invalid input/references and other permanent HTTP failures stop immediately with a failure summary. An exhausted transient failure has unknown server admission status; resubmit the same file to resolve safely by deduplication. Successful earlier packets stay stored, so restart the sender with the same file. Entire JSONL is validated before the first POST. Sender accepts simulator packets only; pacing requires nondecreasing timestamps. Long physical-time gaps intentionally make paced mode slow.
