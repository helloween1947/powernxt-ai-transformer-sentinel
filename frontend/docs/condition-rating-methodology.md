# condition-rating-prototype-v1 · unvalidated display policy

This pure frontend policy is a rules-based demonstration, not an official Health Index, safety assessment, failure probability or RUL. No result is persisted to the backend or added to the telemetry CSV. Sample calculation is explicitly SAMPLE / SIMULATED and excluded from backend mode.

Intended weights: loading 35, measured top-oil thermal 35, approved electrical imbalance 15, oil minimum 15. At least two eligible groups and 50% intended base weight are required. Weighted mean includes only eligible factors; coverage is independent of condition and never called confidence. The current configuration contract provides max_load_pct and max_top_oil_temp_c only. No approved imbalance/minimum-oil rule exists, so those groups are excluded. Loading uses the capacity-loading output, never substitutes worst-phase loading. Residual and estimated oil do not substitute for measured oil.

Eligibility requires genuine finite supported value, expected unit, good input quality, matching reading/asset/source/run/time/configuration, and a returned configured/approved limit with explicit provenance. Recognized configuration provenance includes nameplate/measured/assumed/simulated; the factor explanation preserves it. An assumed setting is not a calibrated manufacturer limit. Current configuration is used only if its version matches the inspected reading. Contradictory, suspect, bad, absent or unit-incompatible evidence is excluded. No missing sensor deducts physical-condition points.

Positive maximum rule: >limit is breached; [0.90×limit, limit] is a provisional warning zone; lower values are normal in this prototype only. A future reviewed positive minimum rule reverses the comparison and provisionally warns from limit through limit/0.90. Nonpositive limits are unsupported by this ratio policy. Sub-scores normal=100, warning=70, breached=25; score bands >=85 lower indication, >=50 review evidence, otherwise elevated indication. None are calibrated safety classes. Any configured breach remains exposed independently of the aggregate score.

Device evidence older than 120 seconds is labelled stale, retaining its measurement time and last frontend evaluation time. Simulation/replay is explicitly stored context. Evidence >30 seconds in the future suppresses the score; clock synchronization is a dependency. Historical inspection is clearly labelled. Policy version is explicit; adding future factors or changing scoring requires a reviewed new version and deterministic tests.
